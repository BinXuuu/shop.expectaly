# 项目需求文档（PROJECT_REQUIREMENTS）

> 状态：Stage 00 建立，内容来自项目初始需求说明，后续阶段可在此基础上补充细化。

## 1. 项目基本信息

- **中文名称**：意料之中～意购
- **英文品牌（暂用）**：Expectaly Shop
- **主站域名**：expectaly.com
- **商城子域名**：shop.expectaly.com
- 本项目只开发商城附属网站，需为未来与主站共享账号系统预留接口（见 [MAIN_SITE_INTEGRATION.md](./MAIN_SITE_INTEGRATION.md)）。

## 2. 项目定位

意大利小众品牌集合店 + 意大利本地买手平台 + 意大利代购资源整合平台 + 收藏品与生活方式商品展示平台。商品由**平台自营**与**入驻商家**共同组成，包括但不限于：

意大利小众饰品、Favilli/Humilis 等品牌、国际米兰周边及手办、法拉利车模、收藏级手办、汽车模型、家居设计产品、意大利手工艺品、香氛及生活方式商品、限量收藏品、雪茄及相关收藏产品、用户自定义代购需求。

前期核心价值是**资源整合与流量撮合**：不强制平台抽成，也不强制用户必须在平台内付款。

## 3. 平台角色（11 种）

1. 游客
2. 普通用户
3. 入驻申请中的用户
4. 已认证商家
5. 平台自营运营人员
6. 内容编辑
7. 客服
8. 商品审核员
9. 商家审核员
10. 管理员
11. 超级管理员

权限判断不能只在前端隐藏按钮，数据访问层必须同时校验，详见 [ROLES_AND_PERMISSIONS.md](./ROLES_AND_PERMISSIONS.md)。

## 4. 商品体系

- **来源**：平台自营 / 入驻商家发布，每个商品记录发布主体。
- **交易标签**（可多选，与分类分开设计）：意大利现货、国内现货、预订、代购、拼单、询价、限量、独家、即将到货、已售罄。
- **初始分类**：小众饰品、时尚配饰、足球周边、国际米兰专区、法拉利及汽车模型、收藏手办、家居设计、意大利工艺品、香氛与生活方式、限量收藏、雪茄及相关收藏、其他意大利好物（管理员可增删排序）。
- **交易模式**（商家按商品配置）：仅展示 / 联系商家 / 添加微信 / 人工询价 / 提交代购需求 / 加入预订 / 加入拼单 / 平台交易。第一期主要实现展示、加入购物车/意向清单、人工询价、联系方式与微信二维码、自主协商状态记录；平台支付**暂不真正启用**，但需预留数据结构和接口。

## 5. 登录与账号体系

- 第一阶段：邮箱/手机号模拟登录 + Supabase Auth + 开发环境验证码流程。
- 微信登录：先建立 provider 类型、OAuth 回调路由、身份绑定数据结构、前端入口、未配置时的友好提示，**不得虚构已完成真实微信开放平台接入**。
- 主站账号互通：为共享 Supabase 项目 / 共享用户库 / 统一认证服务 / 跨子域 SSO 之一预留架构，详见 [MAIN_SITE_INTEGRATION.md](./MAIN_SITE_INTEGRATION.md)。本次不得直接修改 expectaly.com 主站。

## 6. 用户端页面（节选，完整见 [ROUTES.md](./ROUTES.md)）

首页、商品发现页、商品详情页、品牌页、商家主页、城市选品页、主题策展页、搜索页、自定义代购页、平台说明页、法律与政策页面、用户中心（订单/询价/代购/购物车/收藏/浏览历史/地址/评价/设置等）。

## 7. 购物车与询价系统

购物车不做统一支付假象：按商家分组，区分可平台下单 / 需人工询价 / 仅联系商家 / 预订 / 拼单商品，显示原始货币与参考换算价格。询价单记录用户、商品、商家、规格、数量、预算、报价、状态（待商家回复/商家已报价/用户已查看/协商中/已达成/已取消/已过期）等，第一期允许转到微信沟通。

## 8. 订单与代购进度

- **自主交易**：平台不参与付款、发货、售后责任，状态简化为已联系商家/协商中/已达成/已取消/用户手动标记完成。
- **平台交易**：预留完整状态机（已提交 → … → 已完成 / 售后中 / 已退款 / 已取消），第一期不启用真实支付，但页面、状态机、数据库结构保留。

## 9. 价格与汇率

价格字段包含原始价格/货币、人民币与欧元参考价、是否含各类运费/服务费/税费、是否到手价、定金、价格有效期等。所有换算价格需注明：“参考汇率换算，最终价格以商家或平台确认结果为准。”第一期使用可配置的模拟汇率或后台手动汇率。

## 10. 商家入驻与商家后台

入驻申请含商家类型、资质、联系方式、微信二维码、主营类别、发货地点、售后规则等；审核状态：草稿/已提交/审核中/要求补充资料/审核通过/审核拒绝/暂停营业/已封禁。商家后台涵盖商品、库存、询价、订单、拼单、预订、评价、店铺内容、数据统计等。商品发布后默认进入平台审核，未审核不得公开。

## 11. 平台管理后台

仪表盘、用户管理、商家管理、商品管理、订单管理、内容管理、系统配置、权限与日志等模块，详见 [ROUTES.md](./ROUTES.md) 与 [ROLES_AND_PERMISSIONS.md](./ROLES_AND_PERMISSIONS.md)。

## 12. 受限制商品（雪茄等）

需要年龄确认（`age_restricted`、`minimum_age`、`restricted_regions`、`compliance_status`、`requires_manual_review`、`legal_notice_id` 字段）、强制人工审核、地区限制、后台可关闭分类，页面需展示法律提示。禁止通过营销文案鼓励烟草消费。详见 [COMPLIANCE.md](./COMPLIANCE.md)。

## 13. 评价与举报

区分“已验证购买”评价与普通体验评价；举报支持商品/商家/评价/侵权/虚假信息/违规商品/可疑交易/未成年人风险等类型，后台处理流程：待处理/调查中/已处理/已驳回/已下架/已封禁。

## 14. 通知系统

第一期实现站内通知 + 开发环境邮件占位，预留短信与微信模板消息接口。

## 15. 多语言

架构预留简体中文 / 意大利语 / 英语，第一期保证简体中文完整可用，文案统一走翻译文件，不硬编码。

## 16. SEO 与分享

title/description/OG/Twitter Card/canonical/sitemap/robots.txt/结构化数据/面包屑/语义化 HTML，开发环境不得被搜索引擎索引。

## 17. 支付系统预留

第一期 `payment_enabled = false`，前台显示：“平台担保交易正在逐步开放，当前商品请根据页面说明联系商家或提交询价。”不得出现虚假“支付成功”。详见 [PAYMENT_RESERVATION.md](./PAYMENT_RESERVATION.md)。

## 18. 技术栈

Next.js（最新稳定版）、React、TypeScript（严格模式）、Tailwind CSS、shadcn/ui（参考，去模板感）、Supabase / PostgreSQL / Supabase Auth、Zod、React Hook Form、Lucide Icons、next-intl（多语言）、ESLint、Prettier、Vitest、Playwright、npm（本机无 pnpm，已按需求使用 npm）。

## 19. 视觉方向

现代极简、高级、克制、编辑式、可信、具有意大利设计感的精品买手店风格；配色以白/暖白/浅灰/深灰/黑为主，克制使用一种低饱和强调色（深酒红/暗橄榄绿/深咖色三选一）；直角或极小圆角卡片，无胶囊按钮泛滥、无玻璃拟态、无花哨渐变、无促销红、无淘宝式标签、无密集瀑布流、无倒计时抢购；仅使用克制动效并尊重 `prefers-reduced-motion`。

## 20. 验收标准

详见任务原始说明第三十三节；核心要求：可安装依赖、可启动、可生产构建、核心用户/商家/管理员流程完整、双货币与汇率逻辑可用、限制商品具备年龄确认与审核机制、移动端可用、无模板感/淘宝感、未修改其他项目、每阶段独立备份、文档完整、无严重 TS 错误或权限漏洞、无虚假支付成功、无真实密钥入库。
